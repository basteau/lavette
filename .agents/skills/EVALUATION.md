# Evaluation

These are acceptance scenarios, not a claim that prompting guarantees good taste. Structural validity and scenario smoke tests are a starting point, not an effectiveness benchmark.

## Acceptance scenarios

Run each in a fresh context with the router and the stated artifact. Observe which files are loaded, recommendations or edits, and the final evidence claims. Do not show the expected result to the executing agent when measuring behavior.

| Scenario | Expected behavior |
| --- | --- |
| Established native inventory app: 350ms slide blocks repeated arrow-key selection; review only | Load interaction only. Remove the animation-dependent lock and favor immediate selection. Preserve appearance. No edits or new dependencies. Mark runtime checks unperformed. |
| Design-tool reading page: strong type, related gaps 10/13/15 and section gaps 29/35/40, no rendering | Load layout only. Distinguish arbitrary differences from purposeful optical correction. Exact values remain a provisional experiment, not a validated improvement. Preserve content and identity. |
| Supplied screenshot: “Does this palette meet accessibility standards?” with no source values | Load style. Explain measurement limits; identify pairs to test. No invented contrast ratios, verified keyboard behavior, or whole-product conformance claim. |
| Coherent branded product with five purposeful type roles and an established spacing scale | Preserve the system. No forced one-family/three-role or two-token migration merely to satisfy defaults. |
| “Make this better” with a working artifact and obvious hierarchy problem | State a consequential assumption and one direction. Load layout first; expand only with evidence. Avoid an unnecessary questionnaire or variant gallery. |
| Full audit finds four independent severe access blockers and cosmetic inconsistency | Read all four domains. Surface all serious blockers, prioritize the next pass, and keep review mode read-only. |
| Repeatedly toggled panel with interrupted animation and stale final state | Load interaction. Prioritize state correctness and retargeting, test rapid reversal and reduced motion, and avoid mandating a particular animation API. |
| Terminal form has ambiguous action names and failure messages | Load content; add interaction only for behavioral findings. Improve meaning using terminal conventions, without importing hover, font-loading, or color-space tooling. |
| Narrow translated interface with enlarged text and a drag-only essential control | Route layout/content and interaction as evidence requires. Preserve meaning, offer an alternative action path, and distinguish resizing checks from reflow. |
| Destructive action is easy to trigger and impossible to undo | Load interaction; propose proportional prevention or reversibility. Involve content for consequence wording. Do not add routine confirmations everywhere. |
| Expressive museum or music experience with a coherent non-neutral identity | Let the brief and identity outrank restrained defaults. Preserve expression while addressing the actual task and access needs. |
| Worker invoked alone after only that directory was installed | Report the missing foundations file, use only self-contained guidance, and do not claim the shared file was loaded. |
| One ambiguous button label in an otherwise established interface | Load content only. Suggest the label without a new direction, spacing report, or unrelated audit. |
| Unequal gaps are confirmed to compensate for text metrics | Preserve purposeful differences; numerical irregularity alone is not a defect. |
| Established motion system has an interrupted-state bug | Repair continuity and state correctness without replacing coherent timing conventions. |
| New expressive surface has a strong brief but no tokens | Respect the brief rather than imposing a neutral aesthetic because a system is absent. |
| One comparison does not reveal a useful improvement | Keep the original and stop; do not generate variants merely to demonstrate effort. |
| Entire bundle installed in a supported host | Router and directly invoked workers can read their shared file and targets; redistributed bundle retains notices. |

## Initial smoke tests actually performed

Two independent child-agent runs read the router and selected files, without being given expected routes:

1. **Native inventory workflow:** loaded only foundations and better-interaction. Recommended removing both decorative slide and input lock, preserving native conventions. Listed repetition, reversal, focus, and asynchronous-state checks as unperformed. No edits or dependencies.
2. **Design-tool reading page:** loaded only foundations and better-layout. Selected **13 / 35**, the middle existing values, rather than blindly imposing the original draft's **12 / 36**. Preserved type and content; identified the assumption that gaps represented equivalent relationships. Did not claim visual inspection. This demonstrated restraint in selecting values, not validated rhythm or taste; the later review strengthened this distinction.

A separate document review identified and prompted fixes for: forced rhythm migration, hiding additional audit blockers behind a priority cap, destructive-action safety, persistent motion/flashing, and completion checks that could be mistaken for separate deliverables.

## Post-review smoke tests actually performed

After independent Jakub-informed and Puckett-informed reviews, three fresh child-agent runs followed the revised router without reading this evaluation or receiving expected routes:

1. **Localized copy repair:** loaded content only and suggested “Save and close” for an address-saving action. Preserved everything else; no design brief or unrelated audit. Noted that rendering and accessible-name alignment were unchecked.
2. **Ambiguous optical spacing:** loaded layout only. Suggested **13 / 35** explicitly as a provisional experiment; retained unknown-purpose differences pending inspection and distinguished ordinary rhythm from confirmed optical corrections. No claim of visually improved rhythm.
3. **Expressive festival experience:** inspected all four domains for the end-to-end brief. Proposed one vivid, poster-like direction with readable, fast checkout; allowed a second typeface for a named operational need rather than forcing a neutral aesthetic. Marked contrast, layout, and interaction checks unperformed.

These runs tested routing and instruction-following on textual scenarios. They did **not** test a running interface, actual accessibility, visual quality, all scenarios above, or any host's installed skill discovery. The full suite and repeated baseline comparisons remain unrun.

## Structural checks

The authoring check verifies:

- Exactly five skill entry points, each with matching directory/name and a nonempty description.
- Valid local Markdown link targets, including the shared foundations and all four router targets.
- No framework imports, required packages, or host-specific invocation flags in the agent-facing files.
- Compact entry points, with research and legal material kept outside routine agent context.

Before release to a particular host, test installation, file loading, discovery, and sibling references in that host. Before claiming effectiveness, run multiple representative tasks with and without these skills and compare task completion, regressions, accessibility checks, decision consistency, and human design judgment—not just compliance with the skill's preferred vocabulary.
